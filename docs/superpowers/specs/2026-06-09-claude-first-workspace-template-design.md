# Claude-First Workspace Template — Design

Date: 2026-06-09
Author: Clement VEROVE
Status: Proposed (awaiting review)

## 1. Goal

Convert the existing multi-IDE `agent-factory` template into a **Claude-first** project
template, and produce a **Claude-only** twin in the freshly cloned `claude-workspace`
repo. The template must be:

- **Token-efficient** — minimal always-on context; knowledge pulled on demand.
- **Feature-first** — a single `/setup` run yields a runnable, stack-aware project.
- **Not over-engaged** — no hard commitment to a stack or pattern; direction stays
  editable by changing Claude procedures/rules while developing.
- **Best-practice / long-term first** — new patterns are verified against current best
  practices (Context7 / web) before being integrated.

## 2. Two repositories, two roles

| Repo | Role | IDE surfaces | Remote |
|------|------|--------------|--------|
| `agent-factory` | Multi-IDE template | `.claude/` (source of truth) + `.cursor/` + `.agent/` (delegators) | `git@github.com:verovec/agent-factory.git` |
| `claude-workspace` | Claude-only template | `.claude/` only (no `.cursor/`, `.agent/`, `AGENTS.md`) | `git@github.com:verovec/claude-workspace.git` (already set) |

`claude-workspace` is produced by copying the finished `agent-factory` and stripping the
non-Claude surfaces. Both are **project templates**: you clone one to start a project,
run `/setup`, and the clone *becomes* that project's repo.

> Note: `agent-factory` currently points (incorrectly) at `claude-workspace.git`. Its
> origin is repointed to `git@github.com:verovec/agent-factory.git` during the git step.

## 3. Architecture: native-first, lean

The legacy approach front-loaded knowledge into large always-read agent-tree files
(MASTER / SUB-MASTER / APPLICATION…). That is token-heavy and high-maintenance. The new
model uses Claude Code's native primitives and pulls knowledge on demand:

| Layer | Mechanism | When loaded |
|-------|-----------|-------------|
| Always-on rules | lean `CLAUDE.md` (rules + pointers only) | every turn |
| Knowledge | `.claude/skills/*` (coding philosophy, per-stack guides, Linear rules) | on demand |
| Code structure | **Understand-Anything** plugin (code knowledge graph) + Context7 (library docs) | on demand |
| Noisy/specialist work | `.claude/agents/*` subagents (isolated context) | on demand |
| Non-negotiables | `.claude/hooks/*` | invisible, on matching events |
| Orchestration + planning | `/setup`, `/roadmap`, `/card` commands + roadmap state file | on invocation |

The agent-tree **templates** are retained under `templates/` but are **optional** —
generated only when a project grows large enough to need orchestration. They are no
longer the always-loaded default.

Rationale (2026 conventions): every loaded line in `CLAUDE.md`/skills is a recurring
token cost; "brevity is a performance requirement." Always-needed rules go in
`CLAUDE.md`; context-specific knowledge goes in skills; investigation goes to subagents
to keep the main context clean.

## 4. Target repository structure

```
workspace-root/                 # the monorepo; cloned once per project
  CLAUDE.md                     # lean always-on (rules + pointers)
  AGENTS.md                     # universal/antigravity pointer (agent-factory only)
  SETUP.md                      # human-readable setup guide
  README.md
  VERSION
  .gitignore
  .mcp.json                     # lean default MCP set, committed, placeholders only
  .vscode/                      # workspace settings + recommended extensions
  .github/
    workflows/                  # reusable building blocks + thin triggers (see §7)
  .devcontainer/                # root-level (recommended; see §4.1)
  .claude/                      # SOURCE OF TRUTH
    settings.json               # enableAllProjectMcpServers, hook wiring, statusline
    commands/
      setup.md                  # the /setup bootstrap wizard (flagship)
      roadmap.md                # sync roadmap state from Linear (token-optimized)
      card.md                   # create/update Linear cards
      research.md               # verify best practice + latest version for a pattern
      mayday.md                 # help/menu entry that routes to the commands above
      version.md                # compare VERSION vs Linear version card
    skills/
      coding-philosophy/SKILL.md
      roadmap-linear/SKILL.md   # ALL Linear card rules (moved off always-on)
      research-patterns/SKILL.md
      # per-stack skills generated by /setup (e.g. nextjs/, fastapi/, terraform-aws/)
    agents/
      researcher.md             # online/Context7 best-practice + version research
      reviewer.md               # focused code review (isolated context)
      scaffolder.md             # runs stack init CLIs during /setup
    hooks/
      guards.sh                 # no-emoji + only-requested-files style guards
    scripts/                    # helpers used by commands/hooks
  .cursor/                      # KEPT. commands/ + workflows delegate to .claude/
    commands/*.md               # 1-line delegators -> ../.claude/commands/<x>.md
    rules/*                     # kept
    procedures/*                # kept (still referenced by commands)
  .agent/                       # KEPT. workflows delegate to .claude/
    workflows/*.md              # 1-line delegators
    rules/agent-system.md       # kept (mirrors CLAUDE.md rules)
  templates/                    # agent-tree templates (OPTIONAL, generated on demand)
    ...                         # existing set, trimmed; config/ retained
  stack/                        # was repos/ — the project monorepo (COMMITTED, not gitignored)
    backend/
    frontend/
    terraform/
    docs/
    .devcontainer/              # only if not promoted to root (see §4.1)
    .gitkeep                    # in the template, stack/ ships empty
```

### 4.1 `.devcontainer` location

You grouped `.devcontainer` under `stack/`. Recommendation: place it at the **repo root**
so VS Code / Codespaces auto-detect it (the workspace root is now the repo root). This is
the standard and supports "works out of the box." Flagged as a micro-decision — default
to root unless you prefer it scoped under `stack/`.

### 4.2 `stack/` is committed, not gitignored

Model change: the workspace *is* the monorepo, so `stack/` holds the actual project code
and is committed to the project's own GitHub repo (created by `/setup`). In the template,
`stack/` ships empty (`.gitkeep`). `.factory-state.json` stays gitignored (per-workspace).
`.mcp.json` is committed with placeholders only — no secrets.

## 5. Source-of-truth flip (Cursor stays working)

Commands and skills are authored once under `.claude/`. The other surfaces delegate:

- `.cursor/commands/<x>.md` → one line: "Follow `.claude/commands/<x>.md`."
- `.agent/workflows/<x>.md` → same delegation.
- `.cursor/rules/` and `.cursor/procedures/` are kept (commands still reference
  procedures). `.agent/rules/agent-system.md` kept as a mirror of the `CLAUDE.md` rules.

`claude-workspace` drops `.cursor/`, `.agent/`, and `AGENTS.md` entirely.

## 6. The `/setup` command

Flagship bootstrap wizard. Idempotent where possible; confirms destructive steps.

1. **Preconditions** — verify `git`, `gh` (authenticated), `node`/`npx`; report any gaps.
2. **Detach from template** — confirm, then `git remote remove origin` (drops the template
   remote so the clone becomes an independent project).
3. **Project identity** — ask name, slug, short description, visibility (private/public).
4. **Stack questions**
   - Frontend technology (e.g. Next.js, React+Vite, SvelteKit, none).
   - Backend technology (e.g. FastAPI/Python, NestJS/Node, Go, none).
   - Infrastructure is **always Terraform on AWS** — ask only region + state backend.
   - Optional MCP menu — which optional servers to enable (DB, browser, etc.).
   - CI — which `.github` workflows to enable, based on the chosen stack.
5. **Scaffold runnable skeleton** (via `scaffolder` subagent) — using official **latest**
   CLIs, versions verified through Context7/registry:
   - frontend: e.g. `npx create-next-app@latest stack/frontend …`
   - backend: framework init (e.g. uv + FastAPI skeleton, or `nest new`)
   - terraform: minimal AWS skeleton (providers, remote state, env layout)
   - `.devcontainer` + `docker-compose` for local dev
6. **Generate Claude config tuned to the stack**
   - Write a lean project `CLAUDE.md` with project facts + pointers.
   - Generate per-stack skills under `.claude/skills/` from templates, filled with the
     chosen tech and current best-practice notes (researcher subagent).
   - Wire `.mcp.json` with the chosen optional servers (placeholders for secrets).
   - Optionally generate a lean agent-tree (master + roadmap) only if the user opts in.
7. **GitHub** — create the new repo (`gh repo create`, github MCP fallback), set as
   `origin`, make the initial commit, push.
8. **Linear (optional)** — create/link a Linear project + populate roadmap state.
9. **Best-practice pass** — researcher subagent confirms latest versions + integration
   notes for the chosen stack; records them in the relevant skill.
10. **Summary** — what was created, enabled MCPs, next steps.

## 7. `.github` CI (modeled on synquery, kept lean + dynamic)

Adopt synquery's **reusable-building-block** pattern: thin trigger workflows call shared
`_*.yml` reusable workflows.

- Reusable blocks: `_lint.yml`, `_test.yml`, `_terraform.yml` (plan/apply),
  `_deploy.yml`, `_compute_tag.yml`.
- Triggers: `pr.yml` (lint + test on PR), `terraform.yml`, `deploy.yml`.
- Parameterized so `/setup` enables only the workflows relevant to the chosen stack
  (e.g. skip frontend lint when there is no frontend). Unused workflows are removed by
  `/setup`, not left as dead files.

(The exact reusable-workflow shapes are extracted from synquery's `_*.yml` during
implementation — structure only, no project-specific content copied.)

## 8. Tooling: lean defaults + optional menu

**Default `.mcp.json` (committed, placeholders):**
- `context7` — up-to-date library docs (drives the best-practice/version checks).
- `github` — repo/PR operations for `/setup` and ongoing work.
- `linear` — roadmap + card management.

**Default plugin:**
- **Understand-Anything** — code knowledge graph (replaces hand-written structure files).

**Optional menu (offered by `/setup`, off by default):**
- Database MCP (e.g. dbhub), browser/automation MCP, others as they prove out.

This keeps the template un-engaged: the defaults are capability (understand code, fetch
current docs, talk to GitHub/Linear), not a stack opinion.

## 9. Standing rule: verify before integrating

`CLAUDE.md` carries a short rule: *when introducing a new library, pattern, or tool, first
verify current best practices and the latest stable version via Context7 (and web search
if needed) before writing code.* Backed by the `researcher` subagent and the `/research`
command so it is actionable, not just aspirational.

## 10. Token-optimized roadmap + Linear

- Move **all** Linear card rules out of always-on `CLAUDE.md`/`AGENTS.md` into
  `.claude/skills/roadmap-linear/SKILL.md`, loaded only during Linear work.
- The roadmap "agent" becomes a lean generated **state** file (the project's actual cards
  + dependency graph), not a rules document.
- Commands: `/roadmap` (sync state from Linear), `/card` (create/update).
- Preserve existing invariants: fetch issues by identifier (never `search_issues`);
  `teamId`/`projectId` from `.factory-state.json`; never mention agent files in card
  content; no emojis.

## 11. `repos/` → `stack/` rename sweep

Replace folder-path references `repos/` → `stack/` and prose mentions of the `repos`
folder across the repository: `README.md`, `AGENTS.md`, `CLAUDE.md`, `.cursor/procedures/*`,
`templates/*`, `init-agents.md`, and the factory-state schema. Done as a **reviewed**
sweep (each hit inspected), not a blind global replace, to avoid corrupting unrelated
words like "repository." The factory-state `repos` array is reworked to reflect the
single-monorepo model.

## 12. `claude-workspace` duplication

After `agent-factory` is complete:
1. Copy everything **except** `.cursor/`, `.agent/`, `AGENTS.md`.
2. Keep `CLAUDE.md`; adjust README to state it is the Claude-dedicated template.
3. Remote already correct (`claude-workspace.git`).
4. Initial commit + push.

## 13. Out of scope

- No real cloud resources are provisioned (Terraform skeleton only; no `apply`).
- No secrets committed anywhere.
- Antigravity support is delegation-only (no new Antigravity-specific features).

## 14. Phased rollout (for the implementation plan)

1. Restructure `agent-factory` skeleton (`stack/`, root-level config, rename sweep).
2. Build the `.claude/` layer (settings, commands, skills, agents, hooks) + flip Cursor
   delegation.
3. Author the `/setup` wizard + `scaffolder`/`researcher` subagents.
4. Add `.github` reusable workflows + `.devcontainer` + `.vscode` + lean `.mcp.json`.
5. Token-optimize roadmap/Linear into a skill + commands.
6. Repoint `agent-factory` origin (await URL) and commit.
7. Duplicate into `claude-workspace` (Claude-only) and push.
